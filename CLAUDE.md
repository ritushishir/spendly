# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Spendly — a personal expense tracker in Flask + SQLite (stdlib `sqlite3`, no ORM). Python 3.11+.

**This is a teaching scaffold, not a finished app.** Auth and the profile page are built out (Steps 1–5); expense create/edit/delete are still deliberate placeholders that a student implements step by step. When asked to work here, respect that framing: implement the specific step requested rather than filling in all the stubs at once.

Specs for each step live in `.claude/specs/NN-slug.md` and are generated by the `/create-spec` skill. Note that a spec records the plan at the time it was written, not necessarily what shipped — `02`–`05` describe file layouts (e.g. a `database/queries.py`) that the final implementation did not follow. **Read the code, not the spec, to learn the current shape.**

Note the non-default port **5001** (hardcoded in `app.py`), not 5000.

## Architecture

Single-module Flask app — all routes live in `app.py`; there are no blueprints. `database/db.py` is the only intended data-access layer, and routes must go through it rather than opening their own connections.

`app.py` calls `init_db()` then `seed_db()` at import time inside an `app_context()`, so the schema and demo data exist before any request is served.

### `database/db.py`

- `DB_PATH` — `expense_tracker.db` at the repo root (gitignored), anchored via `__file__` so it holds regardless of CWD
- `CATEGORIES` — the fixed seven-category vocabulary (`Food`, `Transport`, `Bills`, `Health`, `Entertainment`, `Shopping`, `Other`). Forms and summaries should import this rather than repeating the strings.
- `SCHEMA` — the `users` and `expenses` tables. `expenses.date` is `TEXT` holding zero-padded ISO `YYYY-MM-DD`, so lexicographic comparison is a valid date comparison. Amounts are `REAL`.
- `get_db()` — connection with `row_factory = sqlite3.Row` and `PRAGMA foreign_keys = ON`. **The caller owns the connection and must close it** — every helper below uses `try/finally`.
- `init_db()`, `seed_db()` — `seed_db()` is a no-op once any user exists and returns `False` in that case
- Users: `get_user_by_email()`, `get_user_by_id()`, `create_user()`, `verify_user()`. Emails are stored normalised (stripped + lowercased); **callers own that normalisation**. `create_user()` returns `None` on a duplicate email rather than raising, and `verify_user()` collapses both failure modes to `None` so a caller can't leak which one it was.
- Expenses: `get_expenses_for_user()` (newest first), `get_category_totals_for_user()` (largest total first)

Every expense query filters on `user_id` — that filter is the only thing keeping one account's spending out of another's page. Never drop or weaken it.

### Route status

Implemented: `GET /`, `GET|POST /register`, `GET|POST /login`, `GET /logout`, `GET /profile`.

Placeholders returning plain strings: `/expenses/add` (Step 7), `/expenses/<int:id>/edit` (Step 8), `/expenses/<int:id>/delete` (Step 9).

Sessions are configured: `app.secret_key` reads `SECRET_KEY` from the environment with a dev-only fallback, login stores `user_id` and `user_name`, and logout calls `session.clear()`. A `login_required` decorator in `app.py` redirects anonymous visitors to `/login` — use it on new authenticated routes, and keep the `@wraps` on it (Flask derives the endpoint name from the function).

`profile()` re-checks that `session["user_id"]` still resolves to a real user and clears the session if it doesn't. Display formatting lives in module-level `_initials()` / `_rupees()` / `_display_date()` helpers so stored rows stay raw and templates print values as-is.

### Templates & styling

Jinja templates extend `base.html`, which defines blocks `title`, `head`, `content`, `scripts`, plus the shared navbar and footer. The navbar renders conditionally on `session.user_id` (signed in: user name + Sign out; signed out: Sign in / Get started).

`static/css/style.css` is hand-written with CSS custom properties defined in `:root` (`--ink*`, `--paper*`, `--accent*`, `--danger*`, `--border*`, `--cat-*` for the category badges, `--font-display`/`--font-body`, `--radius-*`, `--max-width`). Use these tokens rather than literal colors or fonts — the design is a warm-paper / deep-green editorial look, and new UI should match it. No build step, no CSS framework. Reuse the existing `.form-input`, `.btn-primary`, `.btn-ghost`, and `.panel` classes before writing new ones.

Auth templates render a `{{ error }}` string into `.auth-error` when present — follow that pattern (pass `error=` to `render_template`) rather than introducing flash messages, unless asked.

`static/js/main.js` holds only a placeholder comment and is intentionally empty of behaviour.

Amounts are displayed in Indian rupees (₹).
